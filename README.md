# 一戸浄化槽 作業管理システム

浄化槽の保守点検・清掃の現場作業を、スマートフォンのブラウザだけで管理するWebシステムです。アプリのインストールは不要です。

| ご要望 | このシステムでの実現方法 |
|---|---|
| アルコール探知機と連携した出勤管理 | 出勤・退勤のたびにアルコールチェックが必須。検知器の測定値をAPIで受け取り、作業員が「取り込む」だけで判定。基準値を超えたら出勤できず、管理者に危険アラート |
| 顧客の位置を登録し、本当に現場へ行ったか管理 | 顧客ごとに浄化槽の位置（地図でクリック）と許容範囲（初期値100m）を登録。到着・QR読み取り・報告送信の3回とも、サーバ側で現場からの距離を判定 |
| 各自のスマホで位置情報をオンにして会社で管理 | 作業員画面を開くと位置情報の許可を求める。勤務中は位置を定期送信し、管理画面の地図に最終位置と1日の軌跡を表示 |
| 作業報告をそのままシステムから | 作業種別ごとの点検項目（臭気・透視度・pH・残留塩素・ブロワ等）と写真をスマホで入力・送信 |
| 現場に着かないと操作できない | 許容範囲外・位置精度が悪い（初期値：誤差100m超）場合は、到着・QR・報告のいずれも受け付けない。現場外で操作を試みると管理者にアラート |
| 蓋を開けてQRを読まないと報告できない | QRラベルを**蓋の裏側**に貼る運用。QRを読むまで点検記録の入力欄が開かない。QRは改ざん防止の署名付きで、別の浄化槽のQR・再発行前の古いQRは拒否 |

## 作業員の流れ（スマホ）

1. **出勤**：検知器で測定 →「検知器の測定結果を取り込む」→ 0.00 mg/L なら出勤完了
2. **現場到着**：現場で「現在地で到着を確認」（範囲外なら拒否）
3. **QR読み取り**：蓋を開けて、裏側のQRをカメラで読み取る（範囲外・別の槽のQRなら拒否）
4. **点検記録・報告**：点検項目と写真を入力し「現場で報告を送信」（範囲外・最低滞在時間前なら拒否）
5. **退勤**：再度アルコールチェック

出勤していなければ、作業画面は開けません。

## 管理画面（事務所PC）

- **ダッシュボード**：出勤状況、アルコール結果、作業の進捗、地図（現場・従業員の最終位置・軌跡）、アラート
- **作業予定**：日付・担当者・顧客・浄化槽・作業種別を登録
- **顧客・浄化槽**：地図で位置指定（住所検索は国土地理院API）、浄化槽ごとのQRラベル印刷・再発行
- **作業報告**：到着→QR→報告の時刻と現場からの距離、点検結果、写真
- **勤怠・アルコール**：勤怠CSV、アルコールチェック記録簿CSV（不合格も含めて全件。Excelでそのまま開けます）
- **従業員**：アカウントの追加・無効化・パスワード変更
- **設定**：判定基準値、許容範囲の初期値、位置精度、最低滞在時間、検知器連携APIキー、検知器シミュレーター

## 起動方法

Node.js 22.5 以上が必要です（データベースは Node.js 標準の SQLite を使うため、別途のDBサーバは不要）。

```bash
npm install
```

デモデータで試す場合（既存データは消えます）：

```bash
npm run seed
```

```bash
npm start
```

ブラウザで `http://localhost:3000` を開きます。デモのアカウントは次のとおりです。

| 権限 | ログインID | パスワード |
|---|---|---|
| 管理者 | admin | admin1234 |
| 作業員 | sato | sato1234 |
| 作業員 | takahashi | takahashi1234 |

デモデータを入れずに起動すると、初期管理者 `admin` が自動で作られ、パスワードがコンソールに表示されます（`ADMIN_PASSWORD` 環境変数で指定も可）。

### 本番運用の注意：HTTPS が必須です

スマホのブラウザは、**https のサイトでしか位置情報とカメラを使わせません**。本番では次のどちらかで公開してください。

- HTTPS 対応のホスティング（Render、Railway、Google Cloud Run、さくらのVPS＋Caddy など）の背後で動かす
- 証明書を用意して直接起動する：`HTTPS_KEY=key.pem HTTPS_CERT=cert.pem PORT=443 npm start`

| 環境変数 | 内容 |
|---|---|
| `PORT` | 待ち受けポート（初期値 3000） |
| `DATA_DIR` | DB・写真の保存先（初期値 `./data`）。**定期バックアップ必須** |
| `APP_SECRET` | QR署名用の秘密鍵。未指定なら `data/secret.key` を自動生成。**変えると発行済みQRがすべて無効**になるので注意 |
| `ADMIN_PASSWORD` | 初回起動時の管理者パスワード |
| `HTTPS_KEY` / `HTTPS_CERT` | 直接HTTPSで起動する場合の証明書 |

## アルコール検知器との連携

検知器の測定結果を、次のAPIに送信します。クラウド連携型の検知器なら、メーカーのクラウドから転送（Webhook）します。Bluetooth型なら、中継アプリから送信します。

```bash
curl -X POST https://（公開URL）/api/device/alcohol \
  -H "Content-Type: application/json" \
  -H "X-Device-Key: （管理画面の設定に表示されるAPIキー）" \
  -d '{"device_id":"ALC-01","login_id":"sato","value_mgl":0.00,"measured_at":"2026-11-26T07:55:00+09:00"}'
```

- `login_id` は従業員のログインIDです（検知器側の利用者IDと揃えてください）
- 測定値は受信から10分間（設定で変更可）だけ出勤に使えます。1つの測定値は1回しか使えません
- 検知器の機種が決まるまでは、管理画面「設定」の**検知器シミュレーター**で動作確認できます
- 連携できない場合の予備手段として、**手入力＋写真（検知器の表示と本人の顔）**も使えます（設定で無効化可）

## QRラベルの運用

1. 管理画面「顧客・浄化槽」で浄化槽を登録 →「QR印刷」
2. 耐水ラベルに印刷し、**点検口の蓋の裏側**に貼る（蓋を閉めた状態では読めない位置）
3. ラベルが劣化・紛失したら「QR再発行」→ 古いQRは自動で無効になる

## テスト

Playwright によるE2Eテストを18本用意しています。スマホ画面での実操作に加え、位置情報の偽装（現場・5km先・精度不良）と、偽カメラ映像からの実際のQR読み取りを含みます。

```bash
npm run test:e2e
```

テストは一時ディレクトリに専用DBを作るため、本番データには触れません。QRの偽カメラ映像の作成に `ffmpeg` を使います。

## 仕組み上の限界（導入前にご確認ください）

- **画面を閉じると位置送信は止まります**。Webブラウザはバックグラウンドで位置を送れません。ただし到着・QR・報告の3時点は、その場で必ず位置を確認します。常時追跡が必須なら、ネイティブアプリ化を検討します
- **位置偽装アプリを完全には防げません**。そのため位置だけに頼らず、「蓋の裏のQR」「現場写真」「最低滞在時間」を組み合わせています
- 地図は国土地理院タイル（無料・登録不要）を使っています。インターネット接続が必要です

## フォルダ構成

```
src/
  server.js     API・画面配信（ジオフェンス判定・QR検証・アルコール判定はすべてサーバ側）
  db.js         SQLiteのテーブル定義・設定値
  util.js       パスワード、QR署名、距離計算、写真保存
  seed.js       初期管理者・デモデータ
public/
  index.html    ログイン
  staff.html    作業員画面（スマホ）   js/staff.js
  admin.html    管理画面               js/admin.js
  qr-print.html QRラベル印刷
  shared/checklists.js  作業種別ごとの点検項目（画面とサーバで共用。項目の追加はここだけ）
e2e/            Playwright E2Eテスト
```
